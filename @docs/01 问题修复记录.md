### 修复记录 - 2025-01-27

-   **问题描述：** 提示词编辑后，提示词分类自动变成"无"，且修改后，提示词分类无法被修改。

-   **根本原因（可选）：** 
    1. 在编辑模式下，如果 `prompt.category` 是空字符串、null 或 undefined，分类会变成空值
    2. Select 组件无法正确处理空值，导致分类无法显示和修改
    3. 当分类为空时，Select 组件的 value 不匹配任何选项，导致无法正常更新

-   **解决方案：** 
    1. 修复 `usePromptForm.ts` 中的分类初始化逻辑
       - 在 `getInitialFormData` 函数中，如果编辑模式下 `prompt.category` 为空，使用默认分类
       - 在 `useEffect` 监听 prompt 变化时，同样处理空分类的情况
       - 提取 `getDefaultCategory` 为独立的 useCallback 函数，确保逻辑一致
    2. 修复 `PromptFormFields.tsx` 和 `PromptEditForm.tsx` 中的分类选择器
       - 确保 Select 的 value 始终是一个有效的分类 ID
       - 如果当前分类不在分类列表中，使用第一个分类作为默认值
       - 在 `onValueChange` 中添加空值检查，确保只更新有效值

-   **影响范围：**
    -   `src/hooks/usePromptForm.ts` - 修复分类初始化逻辑，处理空分类情况
    -   `src/components/PromptFormFields.tsx` - 修复分类选择器，确保能正常显示和修改
    -   `src/components/PromptEditForm.tsx` - 修复分类选择器，确保能正常显示和修改

**功能特性：**
- ✅ 编辑提示词时，如果原分类为空，自动使用默认分类
- ✅ 分类选择器可以正常显示和修改
- ✅ 确保分类值始终有效，不会出现空值

**技术亮点：**
- 使用 useCallback 优化默认分类获取逻辑
- 在多个地方统一处理空分类的情况
- 确保 Select 组件的 value 始终有效

### 修复记录 - 2025-01-27

-   **问题描述：** 新建提示词的右键弹出菜单的点击范围目前受限制于提示词的数量，如果只有一个卡片，菜单只能在那一个卡片附近弹出，点击其他空白区域则没反应。

-   **根本原因（可选）：** `ContextMenuTrigger` 包裹的容器没有占满整个 ScrollArea 的视口，导致右键菜单的触发范围仅限于有内容（提示词卡片）的区域。当只有一个卡片时，空白区域无法触发右键菜单。

-   **解决方案：** 
    1. 修改 `PromptList.tsx` 中 `ContextMenuTrigger` 包裹的容器样式
    2. 为容器添加 `minHeight: '100%'` 和 `height: '100%'` 样式，确保它占满整个 ScrollArea 的视口
    3. 这样无论提示词数量多少，整个 ScrollArea 区域都可以触发右键菜单

-   **影响范围：**
    -   `src/components/PromptList.tsx` - 修改 ContextMenuTrigger 包裹容器的样式，确保占满整个 ScrollArea 视口

**功能特性：**
- ✅ 右键菜单触发范围扩展到整个 ScrollArea 区域
- ✅ 无论提示词数量多少，空白区域也可以触发右键菜单
- ✅ 保持原有功能不变，仅修复触发范围问题

**技术亮点：**
- 使用 CSS 样式确保容器占满父容器
- 保持原有组件结构，最小化修改
- 不影响其他功能
