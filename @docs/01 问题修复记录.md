### 修复记录 - 2025-12-04

-   **问题描述：** Vercel 部署后，简单的 API 端点（如 `/api/hello`、`/api/health`、`/api/test`）可以正常工作，但需要通过 catch-all 路由处理的端点（如 `/api/auth/oauth/url`）返回 404，且 Vercel Runtime Logs 中没有任何日志输出，说明请求未到达 `api/[...path].ts` Serverless Function。

-   **根本原因：** 
    1. Vercel 的 catch-all 路由 `api/[...path].ts` 未被正确识别或调用
    2. 可能是文件名中的特殊字符 `[...]` 导致 Vercel 无法正确解析
    3. 或者是 Vercel 的路由优先级问题，具体的 API 文件（如 `api/hello.ts`）优先于 catch-all 路由

-   **诊断步骤：**
    1. 创建简单的测试端点 `api/hello.ts` - ✅ 成功返回 200
    2. 测试 `/api/health` 和 `/api/test` - ✅ 成功返回 200（这两个端点在 `api/[...path].ts` 中注册）
    3. 测试 `/api/auth/oauth/url` - ❌ 返回 404，且无日志
    4. 结论：Vercel 能识别简单的 API 文件，但 catch-all 路由未被调用

-   **待验证的解决方案：**
    1. **方案 1：** 重命名 `api/[...path].ts` 为 `api/[...].ts` 或 `api/[...slug].ts`，测试 Vercel 是否能识别
    2. **方案 2：** 使用 Vercel 的 `routes` 配置明确指定 catch-all 路由
    3. **方案 3：** 将所有路由拆分为独立的 API 文件（不推荐，维护成本高）
    4. **方案 4：** 检查 Vercel 构建日志，确认是否识别了 catch-all 路由

-   **下一步行动：**
    1. 查看 Vercel Dashboard 的构建日志（Build Logs），确认是否显示：
       - "Detected Serverless Functions"
       - 是否包含 `api/[...path].ts`
    2. 如果构建日志中没有识别到 catch-all 路由，尝试方案 1 或 2
