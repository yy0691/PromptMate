### 修复记录 - 2026-01-17 (OAuth 登录失败)

-   **问题描述：** Linuxdo 和 Google 账户登录失败，控制台显示 `invalid request: both auth code and code verifier should be non-empty` 错误，同时 Linuxdo 登录被错误地识别为 Google 登录。

-   **根本原因：** 
    1. **Provider 检测失败**：Linuxdo OAuth 回调 URL 中没有 `provider` 参数，`AuthCallback.tsx` 默认将其识别为 Google，导致走错了认证流程
    2. **PKCE code_verifier 丢失**：当浏览器弹窗被阻止时，前端使用 `window.location.href` 直接跳转到 OAuth URL，页面被替换后，Supabase SDK 内部存储的 code_verifier 无法在回调页面中被正确获取

-   **解决方案：** 
    1. **修复 Provider 检测逻辑**：
       - 在 Linuxdo OAuth URL 中添加 `provider=linuxdo` 参数（后端 `linuxdoOAuth.ts`）
       - 在 Google/GitHub OAuth URL 中也添加 `provider` 参数到 redirect_uri（前端 `authService.ts`）
       - 增强回调页面的 provider 检测：支持从 URL 参数、sessionStorage、referrer 等多种方式检测
    2. **改善 PKCE 流程**：
       - 当弹窗被阻止时，保存 OAuth 流程标记和 provider 到 sessionStorage
       - 回调页面优先从 sessionStorage 读取 provider
       - 添加更友好的错误提示，指导用户允许弹窗

-   **影响范围：** 
    -   `src/pages/AuthCallback.tsx` - 增强 provider 检测逻辑
    -   `src/services/authService.ts` - 在 redirect_uri 中添加 provider 参数，改善 PKCE 错误提示
    -   `src/components/AuthDialog.tsx` - 弹窗被阻止时保存 OAuth 流程信息
    -   `server/services/linuxdoOAuth.ts` - 在 Linuxdo OAuth URL 和回调中添加 provider 参数

    2. 更新 `env.template` 文件，添加 Supabase 配置说明和示例
    3. 改进错误提示信息，明确告知用户需要配置哪些环境变量

    -   `src/lib/supabase.ts` - 添加占位符值处理，防止崩溃
