# 生产环境多回调地址配置方案

## 📋 问题说明

在生产环境中，PromptMate 有两个版本：
1. **Web 版本**：部署在 Vercel，使用 `https://your-domain.com/auth/callback`
2. **Electron 版本**：桌面应用，使用 `promptmate://oauth`

但 Linux.do OAuth 可能只支持单个回调地址，需要找到解决方案。

## 🔧 解决方案

### 方案 1: 使用中间代理页面（推荐）

创建一个中间代理页面，统一处理所有回调，然后根据来源分发到正确的处理逻辑。

#### 实现步骤

1. **在 Linux.do 中配置单一回调地址**：
   ```
   https://your-domain.com/auth/callback
   ```

2. **创建中间代理页面** (`/auth/callback`)：
   - 接收 Linux.do 的回调
   - 检测运行环境（Web 或 Electron）
   - 如果是 Electron，将回调数据转发到 `promptmate://oauth`
   - 如果是 Web，正常处理回调

3. **代码实现**：
   ```typescript
   // src/pages/AuthCallback.tsx
   useEffect(() => {
     const code = searchParams.get('code');
     const isElectron = !!(window as any).electronAPI;
     
     if (isElectron && code) {
       // Electron 环境：转发到自定义协议
       window.location.href = `promptmate://oauth?code=${code}&provider=linuxdo`;
     } else {
       // Web 环境：正常处理
       handleOAuthCallback(provider, code, redirectUri);
     }
   }, []);
   ```

### 方案 2: 创建两个 OAuth 应用

在 Linux.do 中创建两个 OAuth 应用：
- **Web 应用**：回调地址 `https://your-domain.com/auth/callback`
- **Electron 应用**：回调地址 `https://your-domain.com/auth/electron-callback`

然后创建一个专门的 Electron 回调处理页面，将回调转发到 `promptmate://oauth`。

#### 实现步骤

1. **在 Linux.do 中创建两个 OAuth 应用**：
   - **应用 1（Web）**：
     - 名称：`PromptMate Web`
     - 回调地址：`https://your-domain.com/auth/callback`
     - Client ID: `LINUXDO_WEB_CLIENT_ID`
   
   - **应用 2（Electron）**：
     - 名称：`PromptMate Electron`
     - 回调地址：`https://your-domain.com/auth/electron-callback`
     - Client ID: `LINUXDO_ELECTRON_CLIENT_ID`

2. **创建 Electron 回调处理页面** (`/auth/electron-callback`)：
   ```typescript
   // src/pages/ElectronAuthCallback.tsx
   useEffect(() => {
     const code = searchParams.get('code');
     if (code) {
       // 转发到 Electron 自定义协议
       window.location.href = `promptmate://oauth?code=${code}&provider=linuxdo`;
     }
   }, []);
   ```

3. **根据环境选择不同的 Client ID**：
   ```typescript
   // src/components/AuthDialog.tsx
   const getLinuxdoClientId = () => {
     const isElectron = !!(window as any).electronAPI;
     return isElectron 
       ? import.meta.env.VITE_LINUXDO_ELECTRON_CLIENT_ID
       : import.meta.env.VITE_LINUXDO_WEB_CLIENT_ID;
   };
   ```

### 方案 3: 使用环境变量动态配置（最简单）

如果 Linux.do 支持多个回调地址（用逗号或换行分隔），可以配置：

```
https://your-domain.com/auth/callback
promptmate://oauth
```

但大多数 OAuth 提供商不支持自定义协议，所以这个方案可能不可行。

## ✅ 推荐方案：方案 1（中间代理页面）

### 完整实现

#### 1. 更新 `AuthCallback.tsx`

```typescript
// src/pages/AuthCallback.tsx
useEffect(() => {
  const processCallback = async () => {
    try {
      const code = searchParams.get('code');
      const error = searchParams.get('error');
      const provider = searchParams.get('provider') || 'google';
      
      if (error) {
        throw new Error(error);
      }
      
      if (!code) {
        throw new Error('未收到授权码');
      }
      
      // 检测是否为 Electron 环境
      const isElectron = !!(window as any).electronAPI;
      
      if (isElectron && provider === 'linuxdo') {
        // Electron + Linuxdo：转发到自定义协议
        const redirectUri = 'promptmate://oauth';
        window.location.href = `${redirectUri}?code=${code}&provider=${provider}`;
        return;
      }
      
      // Web 环境或非 Linuxdo：正常处理
      const redirectUri = `${window.location.origin}/auth/callback`;
      await handleOAuthCallback(provider as any, code, redirectUri);
      
      setStatus('success');
      setTimeout(() => {
        navigate('/', { replace: true });
      }, 1500);
    } catch (error: any) {
      setStatus('error');
      setErrorMessage(error.message);
    }
  };
  
  processCallback();
}, []);
```

#### 2. 在 Linux.do 中配置回调地址

只需要配置一个回调地址：
```
https://your-domain.com/auth/callback
```

#### 3. 环境变量配置

在 Vercel 中配置：
```env
# Linux.do OAuth（Web 和 Electron 共用）
LINUXDO_CLIENT_ID=your-linuxdo-client-id
LINUXDO_CLIENT_SECRET=your-linuxdo-client-secret
```

## 🚀 Vercel Serverless Functions 配置

### 问题 2: 确保 Vercel 能识别 Serverless Functions

#### 检查清单

1. **确保 `api/[...path].ts` 文件存在**
   - 文件位置：`api/[...path].ts`
   - 这是 Vercel 的 catch-all 路由

2. **检查 `vercel.json` 配置**
   ```json
   {
     "functions": {
       "api/[...path].ts": {
         "runtime": "@vercel/node@3.0.0",
         "maxDuration": 30
       }
     }
   }
   ```

3. **确保安装了 `@vercel/node`**
   ```bash
   npm install --save-dev @vercel/node
   ```

4. **前端 API 地址配置**
   ```typescript
   // src/services/authService.ts
   const API_BASE_URL = import.meta.env.VITE_API_BASE_URL || 
     (import.meta.env.PROD ? '' : 'http://localhost:8787');
   ```
   
   在生产环境，如果 `VITE_API_BASE_URL` 未设置，会使用相对路径（同域），这样会自动使用 Vercel 的 Serverless Functions。

5. **在 Vercel 中配置环境变量**
   - 不需要设置 `VITE_API_BASE_URL`（使用相对路径）
   - 或者设置为：`VITE_API_BASE_URL=https://your-domain.vercel.app`

### 验证 Serverless Functions

1. **部署后检查**：
   - 访问 `https://your-domain.vercel.app/api/health`
   - 应该返回 `{"status":"ok",...}`

2. **检查 Vercel 函数日志**：
   - 在 Vercel Dashboard → Functions 查看日志
   - 确认请求被正确路由

3. **测试登录功能**：
   - 在 Web 端测试登录
   - 检查浏览器网络请求，确认 API 调用成功

## 🔍 故障排查

### 问题 1: Electron 回调失败

**症状**：Electron 中点击 Linux.do 登录后，无法完成回调

**解决**：
1. 检查 Electron 是否注册了 `promptmate://` 协议
2. 检查 `AuthCallback.tsx` 中的 Electron 检测逻辑
3. 确认回调页面正确转发到自定义协议

### 问题 2: Vercel Serverless Functions 404

**症状**：API 请求返回 404

**解决**：
1. 检查 `api/[...path].ts` 文件是否存在
2. 检查 `vercel.json` 配置
3. 确认安装了 `@vercel/node`
4. 检查 Vercel 部署日志

### 问题 3: API 请求跨域错误

**症状**：浏览器控制台显示 CORS 错误

**解决**：
1. 检查 `CORS_ORIGINS` 环境变量
2. 确保包含你的域名
3. 检查 `api/[...path].ts` 中的 CORS 设置
