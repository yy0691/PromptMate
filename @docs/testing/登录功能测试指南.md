## 🚀 准备工作

### 1. 环境配置

#### 后端环境变量

复制并配置后端环境变量：

```bash
cd server
cp env.template .env
```

编辑 `server/.env`，填入以下配置：

```env
# Supabase 配置
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_ANON_KEY=your-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key

# OAuth 配置（Linuxdo 必需）
LINUXDO_CLIENT_ID=your-linuxdo-client-id
LINUXDO_CLIENT_SECRET=your-linuxdo-client-secret

# Google 和 GitHub 的客户端 ID 和密钥在 Supabase Dashboard 中配置
# 如果需要，也可以在这里配置：
GOOGLE_CLIENT_ID=your-google-client-id
GOOGLE_CLIENT_SECRET=your-google-client-secret
GITHUB_CLIENT_ID=your-github-client-id
GITHUB_CLIENT_SECRET=your-github-client-secret
```

#### 前端环境变量（可选）

如果需要自定义 API 地址：

```bash
cp env.template .env.local
```

编辑 `.env.local`：

```env
VITE_API_BASE_URL=http://localhost:8787
```

### 2. Supabase 配置

#### 配置 OAuth 提供商

1. 访问 [Supabase Dashboard](https://supabase.com/dashboard)
2. 进入你的项目
3. 导航到 **Authentication** → **Providers**
4. 启用并配置以下提供商：

**Google OAuth:**
- 启用 Google 提供商
- 填入 Client ID 和 Client Secret（从 Google Cloud Console 获取）
- 回调 URL: `https://your-project.supabase.co/auth/v1/callback`

**GitHub OAuth:**
- 启用 GitHub 提供商
- 填入 Client ID 和 Client Secret（从 GitHub Settings 获取）
- 回调 URL: `https://your-project.supabase.co/auth/v1/callback`

#### 配置 Redirect URLs

在 Supabase Dashboard → **Authentication** → **URL Configuration** 中添加：

**Site URL:**
```
http://localhost:5173
```

**Redirect URLs:**
```
http://localhost:5173/auth/callback
http://127.0.0.1:5173/auth/callback
promptmate://oauth
```

### 3. 启动服务

#### 方式 A: 本地开发（推荐）

```bash
# 终端 1: 启动后端
cd server
npm install
npm run dev
# 后端将在 http://localhost:8787 启动

# 终端 2: 启动前端
npm install
npm run dev
# 前端将在 http://localhost:5173 启动
```

#### 方式 B: Vercel 开发模式

```bash
# 安装 Vercel CLI（如果还没有）
npm install -g vercel

# 启动 Vercel 开发服务器
vercel dev
# 这会同时启动前端和 API 路由
```

## 📧 测试邮箱登录

### 步骤 1: 注册账号

1. 打开浏览器访问 `http://localhost:5173`
2. 点击右上角的**登录**按钮
3. 切换到**注册**标签
4. 填写以下信息：
   - 邮箱：`test@example.com`
   - 密码：至少 6 个字符
   - 昵称：`测试用户`
5. 点击**注册**按钮
6. 检查邮箱，点击验证链接（如果启用了邮箱验证）

### 步骤 2: 登录

1. 在登录表单中输入邮箱和密码
2. 点击**登录**按钮
3. 检查是否成功登录：
   - ✅ 右上角显示用户头像/昵称
   - ✅ 浏览器控制台无错误
   - ✅ localStorage 中存储了 token（可在开发者工具中查看）

### 验证登录状态

打开浏览器开发者工具（F12），在 Console 中输入：

```javascript
// 检查 token
localStorage.getItem('access_token')

// 检查用户信息
localStorage.getItem('user')
```

### Linuxdo OAuth 登录

#### 重要：配置回调地址

在 Linux.do OAuth 应用中，回调地址必须设置为：

**开发环境：**
```
http://localhost:5173/auth/callback
```

**生产环境：**
```
https://your-domain.com/auth/callback
```

⚠️ **注意：** 回调地址必须与代码中构建的完全一致，包括协议、域名、端口和路径。

#### 使用测试工具

```bash
node scripts/test-login.js linuxdo
```

#### 手动测试

1. 确保在 Linux.do 中配置了正确的回调地址
2. 打开 `http://localhost:5173`
3. 点击**登录**按钮
4. 点击**Linux.do** 登录按钮
5. 浏览器会打开 Linux.do 授权页面
6. 登录并授权应用
7. 自动跳转回 `http://localhost:5173/auth/callback?code=xxx`
8. 应用自动处理回调并完成登录

#### 验证

- ✅ 右上角显示 Linux.do 账号信息
- ✅ 用户信息来自 Linux.do 账号
- ✅ 可以正常使用需要认证的功能

#### 故障排查

如果遇到 `redirect_uri_mismatch` 错误：
1. 检查 Linux.do OAuth 应用中的回调地址配置
2. 确保回调地址为：`http://localhost:5173/auth/callback`（开发环境）
3. 确保回调地址与代码中构建的完全一致

## 🐛 故障排查

### 问题 1: 后端服务无法连接

**错误信息:**
```
❌ 后端服务未运行或无法访问
```

**解决方案:**
```bash
# 确保后端服务已启动
cd server
npm run dev

# 检查端口是否被占用
netstat -ano | findstr :8787  # Windows
lsof -i :8787                 # macOS/Linux
```

### 问题 2: OAuth 授权失败

**错误信息:**
```
redirect_uri_mismatch
```

**解决方案:**
1. 检查 Supabase Dashboard 中的 Redirect URLs 配置
2. 确保包含 `http://localhost:5173/auth/callback`
3. 检查 OAuth 提供商的回调 URL 配置

### 问题 3: 环境变量未配置

**错误信息:**
```
LINUXDO_CLIENT_ID is not configured
```

**解决方案:**
1. 检查 `server/.env` 文件是否存在
2. 确保所有必需的环境变量已配置
3. 重启后端服务

### 问题 4: Supabase 配置错误

**错误信息:**
```
Invalid API key
```

**解决方案:**
1. 检查 `server/.env` 中的 Supabase 配置
2. 确保 URL 和 Keys 正确无误
3. 从 Supabase Dashboard → Settings → API 获取正确的密钥

### 问题 5: 登录后无法获取用户信息

**解决方案:**
1. 检查浏览器控制台是否有错误
2. 检查 localStorage 中是否有 token
3. 检查网络请求是否成功
4. 验证 Supabase 数据库中的用户表是否正确创建
