# 后端服务连接错误解决方案

## 错误信息

```
http proxy error: /api/auth/oauth/url?provider=github&redirect_uri=...
AggregateError [ECONNREFUSED]:
    at internalConnectMultiple (node:net:1139:18)
```

## 问题原因

Vite 开发服务器配置了代理，将 `/api` 请求转发到 `http://localhost:8787`，但后端服务没有运行。

## 解决方案

### 方案 1: 启动后端服务（推荐）

在开发环境中，需要同时运行前端和后端：

```bash
# 终端 1: 启动后端服务
cd server
npm install  # 如果还没安装依赖
npm run dev

# 终端 2: 启动前端服务
npm run dev
```

后端服务将在 `http://localhost:8787` 启动，前端服务将在 `http://localhost:5173` 启动。

### 方案 2: 使用 Vercel 开发模式

如果使用 Vercel Serverless Functions，可以使用 Vercel CLI：

```bash
# 安装 Vercel CLI（如果还没有）
npm install -g vercel

# 启动 Vercel 开发服务器（会自动处理 API 路由）
vercel dev
```

这会同时启动前端和 API 路由，无需单独启动后端。

### 方案 3: 检查后端服务状态

如果后端服务应该正在运行，检查：

1. **端口是否被占用**：
   ```bash
   # Windows
   netstat -ano | findstr :8787
   
   # macOS/Linux
   lsof -i :8787
   ```

2. **后端服务日志**：
   查看后端服务的控制台输出，确认是否有错误。

3. **环境变量配置**：
   确保 `server/.env` 文件存在且配置正确。

## 验证后端服务

访问健康检查端点：

```
http://localhost:8787/api/health
```

应该返回：
```json
{
  "status": "ok",
  "timestamp": "...",
  "service": "PromptMate API"
}
```

## 常见问题

### 问题 1: 后端服务启动失败

**可能原因**：
- 依赖未安装
- 环境变量未配置
- 端口被占用

**解决方法**：
```bash
cd server
npm install
# 检查并配置 .env 文件
npm run dev
```

### 问题 2: 代理仍然失败

**可能原因**：
- Vite 配置缓存
- 后端服务启动较慢

**解决方法**：
1. 重启 Vite 开发服务器
2. 等待后端服务完全启动后再访问前端

### 问题 3: 生产环境部署

在生产环境（Vercel）中，不需要单独启动后端服务，因为：
- API 路由通过 `api/[...path].ts` 作为 Serverless Functions 运行
- 前端使用相对路径，自动使用同域的 API

## 快速检查清单

- [ ] 后端服务是否在运行？
- [ ] 后端服务是否在正确的端口（8787）？
- [ ] `server/.env` 文件是否存在？
- [ ] 环境变量是否配置正确？
- [ ] 是否有端口冲突？
